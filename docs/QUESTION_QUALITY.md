# 如何把 AI 草稿变成可练的题目

本项目用于学习与主动回忆。模型负责生成候选题，固定答案负责判分，使用者负责审核知识与证据；80% 是本轮首答正确率，不是就业能力或独立掌握的认证。

## 选词与考察角度

关键词应包含知识对象、运行机制和边界，避免只填“Java 面试”。例如：

| 领域 | 关键词示例 | 适合的追问角度 |
| --- | --- | --- |
| Java 集合 | equals/hashCode、可变键、碰撞、扩容、Iterator、复合操作 | 给出具体代码和输入，比较查找与并发更新结果 |
| 并发与 JVM | happens-before、volatile、CAS、线程池队列、拒绝、Semaphore、GC | 区分可见性和原子性，追踪积压与资源上限 |
| Spring | 代理、自调用、IOC/AOP、事务传播、rollbackFor、HTTP 幂等 | 根据入口、异常类型和数据库结果判断实际事务 |
| 数据设施 | 索引/MVCC、事务锁、TTL、Lua、Rate Limit、Quota、Offset、幂等消费 | 区分单步与整体原子，分析超时和重复执行 |
| Agent 后端 | Tool schema、参数验证、可信身份、对象级权限、引用、停止条件 | 给出不可信模型输出，预测拒绝层和下游是否调用 |
| 算法思路 | 区间不变量、退出条件、边界值、时间复杂度 | 用小输入跟踪变量变化，避免奇技淫巧题 |

关键词只是请求范围。所上传资料没有讲到的内容，模型不应凭词表补造知识；应补充有权使用的资料再出题。目标是常见实习面试的基础和应用，默认不出冷门记忆题，不使用“以上都对/都不对”凑选项。

## 草稿要求

每题需要明确场景和前提，四个语义不同的选项，单选或多选的确定答案，整体解析、逐项解析、来源段落与逐字证据。干扰项应来自真实误解，例如“volatile 让 ++ 原子”“登录等于有权读取任意订单”，不能靠明显荒谬的文字凑题。

资料作为不可信数据传入模型，不能覆盖出题规则。模型输出必须是规定 JSON；服务器检查结构、题型答案匹配、重复、长度、来源版本和原文引用，失败不会写题库。浏览器先展示全部草稿和证据，再由使用者确认写入。

这些检查不保证答案必然正确，也不证明引用支持该结论。审核时要读完整上下文、确认代码执行条件、逐项判断答案、检查资料许可和私人信息。不要将只有结构检查通过的草稿宣传成专家验证题库。

## 验收边界

出题适配器测试使用受控模型替身，验证协议、拒绝错误与写入边界；没有 API Key 时不会调用真实供应商。接入自己的模型后，先少量生成，检查请求成本、质量与来源，再决定是否增加题量。模型可以依然犯错；不应按模型返回的“可信度百分比”直接自动通过。

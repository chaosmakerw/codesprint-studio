# Redis：计数、过期与脚本边界

原创演示场景：同一应用每个时间窗口最多发起一定数量的模型请求。计数必须并发安全，也应在窗口结束后释放空间。

## 单命令与组合

Redis 的 INCR 是原子命令，但 INCR 和 EXPIRE 两次独立调用并不是一个整体原子操作。若计数已经递增而设置过期前发生失败，键可能长期保留。可以用 Lua 脚本将相关操作放在一次执行中，并根据限流语义决定何时初始化过期时间。

## 固定窗口与过期

每次请求都刷新计数键的 TTL，会把固定窗口悄悄改成持续延长的窗口。固定窗口通常将窗口编号纳入键，并在首次创建时设置合适的过期；不要把 TTL 当作所有限流算法都通用的正确答案。窗口切换边界还可能短时间放行两批请求，需求严格时应评估滑动窗口或令牌桶。

## Lua 不意味着所有错误可回滚

Redis Lua 脚本执行期间避免其它命令交错，但脚本发生运行错误不等于此前已执行的写入自动回滚。应先做必要的参数和类型验证，再进行写操作。脚本必须保持短小，避免长时间阻塞服务器；也不要把网络调用或大批量遍历当成普通 Lua 操作。

## 额度与失败策略

Rate Limit 表示单位时间的请求速率，Quota 表示一个较长计费周期或余额内的累计额度；二者目标不同。当 Redis 不可用时，应按接口风险明确拒绝、降级或保守本地限制，并对外返回稳定错误，不能默默按“无限额度”运行。

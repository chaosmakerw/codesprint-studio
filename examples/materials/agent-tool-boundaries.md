# Agent 工具：参数与身份的信任边界

原创示例：模型可以请求商品搜索、商品详情和查看当前用户订单，后端负责确认什么可以真正执行。

## 模型输出属于不可信输入

工具名与参数来自模型，应先经过工具白名单和原始参数验证，再进行安全类型转换和业务调用。工具 schema 帮助模型理解协议，不能取代服务器校验。对于数量等整数参数，需要检查整数性、范围和转换精度，不能直接调用 Number.intValue 后就认为输入合法。

## 身份与对象级权限

当前用户身份应来自可信服务器上下文，不由模型参数中的 userId 决定。即使用户已经登录、参数也合法，读取订单仍应检查订单是否属于这个用户。参数验证、身份认证与对象级授权是三个不同职责，不能互相代替。

## 稳定失败与内部诊断

工具结果可通过 success、code、message、data 表达成功、参数错误、无权限或依赖失败。意外异常应返回固定安全信息，同时在内部保留不含密钥和正文的诊断信号。统一错误响应不等于根因已修复，也不应把数据库堆栈直接回传给模型或浏览器。

## RAG 引用

引用只能绑定本次实际检索到的片段，由服务器保存可信元数据。模型输出一个看似正式的文档标题或链接，不会因此变成可信证据。资料不足时应拒答或明确缺口，不能补造引用。

## 自己动手

给工具输入合法整数、带小数的数字、越界数和伪造身份。预测失败应在哪层返回，以及下游 service 是否可以被调用；再用测试同时验证合法成功与越权拒绝。

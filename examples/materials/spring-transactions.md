# Spring：事务边界与代理调用

原创演示场景：一个订单服务需要先写订单，再扣减库存，任何一步失败都应按定义回滚。

## 声明式事务的入口

在常见的基于代理的声明式事务模式中，外部调用经过 Spring 代理，事务拦截器才能围绕目标方法执行事务控制。同一个对象内使用 this 调用自身另一个标注事务的方法，通常不会经过该代理。这里的关键是调用路径，而不是“代码里存在注解就一定生效”。不同代理方式和方法可见性也需要按实际配置确认。

## 回滚规则

Spring 声明式事务默认对 RuntimeException 和 Error 回滚，对普通受检异常不默认回滚。若业务需要受检异常触发回滚，应明确配置 rollbackFor，并在测试里检查实际数据状态。异常在方法内部被捕获后正常返回，事务拦截器可能看不到原始失败；不能仅凭页面显示错误文字断言已经回滚。

## 边界与外部系统

数据库事务不会自动撤销已经发送到外部模型、邮件或第三方接口的请求。在事务里持有连接并等待很慢的 HTTP 调用还会延长资源占用。需要结合一致性需求设计请求顺序、补偿、幂等或事务消息，而不是将所有操作包进一个长事务。

## 测试应该看什么

只对 Mock 验证 service 被调用，不能证明数据库事务正确提交或回滚。需要在适当的 Spring 与真实数据库组件测试中，让合法请求提交，再让失败请求走到目标失败位置，验证对应数据没有部分变更，同时明确测试是否真的经过代理。

# 去重范围与判断顺序

来源类型：Agent 原创实例
标题：去重范围与判断顺序

访问事实：2026-10-07，依据本目录原创源码编写；未联网访问外部资料
适用版本：Python 3.12 或以上；本包 NoteQueue 实现
原文使用范围：仅原创教材

`_pending` 是一个字典，键是规范化任务键，值是包含 `key` 和 `text` 的小字典。`key in self._pending` 问的是“这个键现在是否仍在等待”，而非“这份笔记历史上是否处理过”。`enqueue` 成功返回 `True`，重复待处理键返回 `False`，无容量抛出 `OverflowError`。

设 `capacity=1`，先执行 `enqueue("A", "First")`。此时 `_pending` 只有 `"a"`，长度为 1。执行 `enqueue(" a ", "Replacement")`：键规范化为 `"a"`，正文合法，重复条件为真，于是返回 `False`；长度、原正文与插入顺序均不变。

同一满队列改为 `enqueue("b", "New")`：键与正文合法，重复条件为假，容量条件 `1 >= 1` 为真，抛出 `OverflowError`。写入行尚未执行，原任务仍保留。比较这两个输入能看出为什么重复检查必须在容量检查之前。

这个顺序让重复请求得到稳定的去重结果，即使队列已满。返回 `False` 表示没有新增任务；它不代表发生了外部故障。若将容量检查移到去重之前，同一重复键在未满时返回 `False`、满时却抛出异常，契约就改变了。

重复请求不会覆盖正文。需要“更新已有任务”时应该定义另外的业务操作，再确定是否保留排队顺序。把字典赋值直接放在重复判断前会丢掉这一边界。容量限制也只是本实例的待处理条数上限，没有过期、持久化或多实例全局限制。

请预测满队列中的三种情况：有效重复键、有效新键、重复键但空正文。分别写出 `False`、`OverflowError` 或 `ValueError` 的停止位置与保留下来的任务，再提出改变判断顺序会影响哪个结果。

验收要覆盖合法新增、合法重复、容量边界和非法输入，不能只验证抛异常。当前单线程逻辑及单元测试不证明多线程“检查后写入”具有原子性；若增加线程，必须重新设计同步边界。

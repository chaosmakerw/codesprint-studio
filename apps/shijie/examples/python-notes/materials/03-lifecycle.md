# FIFO 与待处理状态变化

来源类型：Agent 原创实例
标题：FIFO 与待处理状态变化

适用版本：Python 3.12 或以上；本包 NoteQueue 实现
原文使用范围：仅原创教材

FIFO 表示先进入队列的先被取出。本实现利用字典保留插入顺序这一语言行为；它既不按键的字母顺序排序，也不取最近加入的任务。`iter(self._pending)` 产生键的迭代器，`next(...)` 取第一个键，`pop(oldest_key)` 删除并返回对应任务。

手算：创建容量 2 的队列，加入 `("b", "First")`，再加入 `("a", "Second")`。内部键顺序为 `b → a`。`take()` 检查非空，令 `oldest_key="b"`，删除 `b`，返回它的数据；内部只剩 `a`。下一次取出是 `a`。

取出释放去重键与容量。上例第一次 `take()` 后，`enqueue("B", "Again")` 会成功，键规范化为 `b`，排在 `a` 后面。内部顺序变为 `a → b`。如果待处理状态为空，`take()` 直接返回 `None`，不会执行 `next` 或 `pop`。

状态顺序是“未在队列 → 待处理 → 被取出”。本实例没有“处理成功”状态：取出以后工作者可能失败，但队列已经不再保存该任务。因此不能把这个短例宣称为可靠任务系统，去重范围也没有覆盖处理中或已完成的历史记录。

这样设计保持代码小、行为可手算，适合学习状态转移。若需要失败重试，必须先定义什么时候确认、失败后是否重新排队、重复键在处理中怎么处理，再选择新的数据结构。简单把 `pop` 改为读取会造成每次取出同一个任务且无法释放容量。

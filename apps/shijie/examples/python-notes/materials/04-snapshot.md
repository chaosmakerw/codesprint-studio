# 返回值与可变对象隔离

来源类型：Agent 原创实例
标题：返回值与可变对象隔离
URL：无
访问事实：2026-10-07，依据本目录原创源码编写；未联网访问外部资料
适用版本：Python 3.12 或以上；本包 NoteQueue 实现
原文使用范围：仅原创教材

快照是某个时刻的数据副本。Python 的列表和字典可变；如果方法直接返回内部对象，调用者改返回值也可能改队列。本实现的 `snapshot()` 同时创建一个新列表，并对每个任务执行 `dict(job)` 创建新字典。

跟踪：队列已有 `{key:"a", text:"First"}`。`view=queue.snapshot()` 后，`view` 指向新列表，其第一个元素指向新字典。内部 `_pending["a"]` 指向另一份字典，两者内容相同，但对象不同。执行 `view[0]["text"]="Outside"` 和 `view.clear()`，只影响外部副本。再次 `snapshot()`，仍得到原来的 `"First"`。

`[job for job in self._pending.values()]` 只创建新列表，元素仍是内部字典。此时 `view.clear()` 不会清空队列，但 `view[0]["text"]="Outside"` 会修改内部任务。必须分别检查外层容器与内层元素，不能因为看见新列表就认定完全隔离。

这里 `dict(job)` 是浅拷贝：嵌套对象不会递归复制。当前任务仅包含字符串，字符串本身不可变，因此足以满足本例的隔离要求。如果以后加入可变 `tags` 列表，原先的浅拷贝便不再阻止 `view[0]["tags"].append(...)` 影响内部数据，需要重新选择不可变结构或复制策略。

`take()` 先将任务从内部移除，再返回它的字典副本。对已取出结果的修改不会重新创建待处理状态。本实例的读取隔离保护对象所有权，不提供线程同步、多实例一致性或持久化保证。

请预测两种修改：清空外部列表、改外部元素正文。再把快照行假设改为仅复制列表，判断哪一种输入会暴露错误；最后给出含 `tags` 列表时的迁移测试草案。

验收应解释“内容相等”与“引用同一可变对象”的区别，提供修改外部结果后再读取的对照。单元测试只覆盖当前字符串字段，未来新增嵌套可变数据必须追加相应验证。
